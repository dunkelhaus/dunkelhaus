Rebuilding a cancer-classification experiment

Five tumor-level classifiers got every final test case right. That is the shortest account of this project, and the least useful one. The test set contained only 22 tumors. Another input matrix contained 92.55% literal NA values whose biological meaning was not verified. This is a walkthrough of rebuilding the experiments, checking their numerical behavior, and separating what the results show from what they cannot establish.

The question was classification, not treatment

The task was to distinguish lung adenocarcinoma from melanoma using mutation-derived inputs. I compared eight pipelines: five mutation representations, M1–M5, and three wide sample-matrix pipelines, S0–S2. Melanoma was label 1 and the positive class. Lung adenocarcinoma was label 0. Decisions used a fixed probability threshold of 0.5.

Mutation signatures provide the biological context. Substitution patterns and neighboring bases can carry information about mutation processes. The pmsignature work models those features with a compact probabilistic representation; the usual joint representation has 96 immediate sequence contexts. This project did not reproduce that paper's signature-extraction model. It rebuilt a local classification workflow with explicit, proposed settings. It did not identify causal signatures or test whether a patient would benefit from treatment.

A new experiment package, not a new portal

The old repository mixed training code, a REST application, browser controls, and copied visualization demos. I added an isolated Python package at src/cancer_therapy/, with a project-local Python 3.12 environment and a locked dependency set. Keras 3 used the PyTorch backend, configured before import. The new commands did not import the legacy REST or TensorFlow application.

That separation does not make modules/ disposable. The old coordinator still imports its database, REST, statistics, and neural-network components. The new package replaces the experiment workflow, not the web portal. I left the legacy tree unchanged rather than combine reproduction with an unrelated application migration.

The source audit changed the interpretation

Preparation verified file hashes, byte sizes, headers, identifiers, and dimensions before fitting. The mutation input needed recovery from an existing Git blob. Recovery refused to overwrite a conflicting destination. Parsing found one recorded malformed row: source line 584851, from lungad_28, had an all-zero first flank group. Excluding that row left 3,520,402 mutations from 110 tumors. That tumor's retained count was 63,861, including for its frequency denominator.

The sample input had the same set of tumor identifiers, but a very different shape: 110 rows and 1,499,663 feature columns. Of its 164,962,930 cells, 152,670,675 were literal NA values. The remaining 12,292,255 cells were numeric observations, including observed zeros. The reader kept these cases distinct and retained every feature position.

Here, “92.55% missing” describes the file encoding and our chosen interpretation. It does not establish that these cells are unknown measurements rather than biological absence. If NA means absence, imputing it as an unknown value can be the wrong model of the data.

This uncertainty should have been resolved before the expensive sample experiments. It was not. Their results are therefore conditional on treating NA as missing. Matching tumor identifiers also do not prove that the two files encode identical underlying mutation records. Neither issue is repaired by a high classification score.

Five ways to represent mutations

One retained mutation has 14 indicators: four for the upstream base, six for substitution type, and four for the downstream base. Exactly one indicator is active in each group. The substitution order is C→A, C→G, C→T, T→A, T→C, T→G; the flank order is A, C, G, T.

M2 loses the association between an upstream base, substitution, and downstream base. M3 keeps it in $4\times6\times4=96$ bins, ordered by upstream base, then substitution, then downstream base. Checks matched the joint histogram's marginals to M2 and its total to the tumor's retained mutation count.

Frequency normalization removes the explicit count denominator, not feature positions. M4 has three groups that each sum to one, so its whole vector sums to three. M5's whole vector sums to one. Neither representation appends mutation burden as another feature.

Keep the unit of prediction and the fit boundary explicit

A seeded, shuffled, stratified 80/20 tumor split gave 88 development tumors and 22 final test tumors. Development contained 34 lung adenocarcinomas and 54 melanomas; final test contained 8 and 14. M2–M5 and S0–S2 used the same saved assignments, matched by identifier rather than input row order. Five stratified folds split the development set. Each development tumor received exactly one out-of-fold (OOF) prediction.

M1 instead split mutation rows: 2,816,321 development rows and 704,081 test rows. Row identities were disjoint, but tumors could recur across partitions. Its question was whether one mutation row predicts a label, not whether a model generalizes to a new tumor. Millions of rows do not become millions of independent patients.

Each fold fitted its scaler, applicable imputer and MDS transform, and a new classifier using only its training scope. Scaling kept constant columns with a scale of one. Validation rows could control neural early stopping, but the final test could not select settings, imputation rank, transforms, or duration. This is the fit/transform boundary needed to avoid preprocessing leakage.

Final refits used all 88 development tumors. Neural duration was the rounded median of the five folds' best epochs, with no final-test early stopping. All settings in this writeup are the settings run, not a claim to have recovered undocumented historical defaults.

Fit the missing-data model inside each training scope

S0 and S1 used all 1,499,663 sample features after imputation and scaling. S2 used the same completed, scaled matrix before MDS. There was no top-feature subset or conversion to mutation proportions.

The imputer fixed each column's mean from observed training entries, centered the matrix, and initialized missing centered entries to zero. It then alternated a rank-$M$ decomposition with replacement of only the missing entries. Observed values were restored exactly at every update. The next decomposition used the updated matrix. A single SVD followed by one fill would not implement this loop.

\hat{x}_{ij}=\mu_j+a_i^{\mathsf T}v_j

In this expression, $\mu_j$ is the fixed training offset, $v_j$ is a basis vector for feature $j$, and $a_i$ contains row coefficients. The rank constraint applies to the reconstruction used for missing values. Restoring observed entries means the completed matrix need not itself have rank $M$.

Rank selection hid 10% of eligible observed training entries in three seeded repeats. Candidates 1, 2, 5, 10, and 20 used the same masks. Mask construction retained observed support for fitting. Mean hidden-entry RMSE selected rank, with lower rank breaking a tie. The selected rank was then refitted on the original observations. These entry holdouts were separate from classifier validation: a good reconstruction score does not establish a good cancer classifier.

A held-out tumor did not trigger another decomposition. Its own observed entries fitted coefficients against the frozen training offsets and basis, using a minimum-norm least-squares solution with relative cutoff $10^{-6}$. Its missing entries were filled from those coefficients. Its observed entries stayed unchanged. Processing one held-out row could not change another row's result or the basis.

Unsupported data required explicit assumptions. A column with no training observations used the global observed training mean and zero basis loadings. A row without usable support used zero coefficients. The final development fit had 73,033 never-observed columns. Those fallbacks retained feature positions; they did not supply evidence about the missing biological values. Negative reconstructions were counted, not silently clipped.

Diagnostics tracked factor reconstruction RMSE on observed entries, relative change in missing values, and stopping reason. Proposed limits were relative change $10^{-4}$, insufficient relative RMSE improvement $10^{-4}$ for five iterations, or a 100-iteration cap. All six classifier-training scopes selected rank 5, but all six refits stopped on a plateau, not convergence. Across 90 rank-selection fits, 44 stopped on plateau and 46 reached the cap. Outputs were finite; finite is not the same as converged.

Classical MDS needs an out-of-sample rule

S2 reduced the completed, standardized features to ten coordinates using Euclidean classical multidimensional scaling. It formed squared distances, double-centered them, and used a symmetric eigensolver. For squared-distance matrix $D^{(2)}$ and centering matrix $H$:

B=-\tfrac12 H D^{(2)}H,\qquad Z=V\Lambda^{1/2}

Components required positive supported eigenvalues. Materially negative spectra and excessive dimension requests were errors, not opportunities to take absolute eigenvalues. Row-Gram or feature-block calculations avoided constructing a distance matrix for every feature.

A new row used squared distances to the frozen training reference. Subtracting its mean distance and the saved training distance means produced a centered vector, projected with the saved eigenvectors and inverse square-root eigenvalues. No joint test embedding was fitted. Training self-projection, reload equivalence, and agreement with PCA scores up to sign or rotation checked this Euclidean implementation; PCA did not replace the experiment.

The final ten components accounted for about 62.0% of the positive spectrum. Coordinates were not standardized again. Neither that percentage nor a visually separated embedding establishes predictive performance. MDS preserves unsupervised geometry, not a label objective.

Make GPU execution and progress observable

The seven neural experiments used hidden layers of 16 and 8 ReLU units, a sigmoid output, binary cross-entropy, Adam at 0.001, and kernel L2 coefficient 0.0001. Fold stopping monitored validation loss with patience 10 and restored the best weights. M1 used batches of 4,096 for at most 50 epochs; the other neural models used batches of 16 for at most 200. No model used class weights. S0 used L2 logistic regression with $C=1$ and an unpenalized intercept.

An early execution problem exposed an important distinction: putting the neural model on CUDA did not put NumPy imputation, MDS, or the CPU logistic solver there. I added explicit GPU numerical paths rather than describe a partly CPU pipeline as fully accelerated. The measured runs used an RTX 2080 Ti. Imputation and MDS used float64 calculations; neural inputs and weights used float32. The GPU logistic path used L-BFGS for the same L2 objective, checked against the CPU implementation. File reading, scaling, mask generation, and serialization remained on CPU.

GPU API behavior mattered for correctness. PyTorch's CUDA lstsq driver assumes full rank, but held-out observed subsets can be rank-deficient. The GPU row projection therefore used an SVD-based minimum-norm solve with the specified cutoff instead of quietly changing that behavior.

Folds and rank candidates ran sequentially. Compatible S0–S2 scopes reused preprocessing only when source hashes, feature order, exact training identities and values, masks, seeds, settings, implementation, and numerical device matched. Checksums protected completed cache entries. Interrupted work remained separate; an unfinished fit was not relabeled complete. Cache reuse also means recorded continuation durations are not clean end-to-end speed benchmarks.

Flushed progress events exposed experiment, fold, rank candidate, repeat, iteration, device, stopping diagnostics, and neural epochs or logistic evaluations. Each run saved these events alongside its configuration, source audit, vocabulary, splits, numerical state, model, history, warnings, versions, code revision and dirty state, and identity-linked probabilities. Reports could be regenerated from saved probabilities without training or loading a model.

What the class metrics add

M2 and M4 each made five OOF errors, but not the same class tradeoff. M2's confusion counts were 31 correct and 3 missed lung tumors, with 2 missed and 52 correct melanomas. M4 had 32 correct and 2 missed lung tumors, with 3 missed and 51 correct melanomas.

M5 made three OOF errors, all melanomas predicted as lung cancer. Its perfect lung recall and perfect melanoma precision are linked consequences of having no lung tumors predicted as melanoma, not two independent achievements. The apparent differences among M2–M5 are only one or two development errors. One split and 88 tumors do not establish a reliable winner.

On the final 22 tumors, M2–M5 and S0 all had confusion matrix [[8, 0], [0, 14]]. Both classes therefore had precision and recall of one on this test set. That is a valid description of these counts, not a claim of perfect population performance. Patient-level independence was not verified, and no external cohort was evaluated.

Plausible explanations are not demonstrated causes

Aggregation gives a tumor classifier many mutations rather than one noisy local observation. Counts preserve burden and composition; frequencies emphasize composition. The strong M4 and M5 results show that an explicit burden feature was not necessary for this split. They do not identify the biological mechanism or exclude technical and cohort confounding.

Tobacco-associated and ultraviolet-associated mutation processes make the lung/melanoma distinction biologically plausible. These classifiers did not estimate signature exposures or establish which signatures caused their decisions. Prediction and signature attribution are different analyses.

The sample results also resist a simple “wide data failed” story. S0 matched the perfect final mutation-model scores. S1 did not: its roughly 24 million neural parameters faced only 88 final-fit tumors, and its final accuracy fell to 14/22. That equals the majority baseline numerically, but its predictions were not all melanoma: its confusion matrix was [[7, 1], [7, 7]]. Parameter count and overfitting are plausible concerns, not a measured causal explanation for the failure.

S2 scored 13/22, with confusion matrix [[7, 1], [8, 6]]. Losing label information through an unsupervised reduction is one hypothesis. Coordinate scale and downstream optimization are others. We did not isolate them. Its 62% spectrum figure is not evidence that it retained 62% of the information needed to classify cancer.

All three sample pipelines share the unresolved NA interpretation and nonconverged imputation diagnostics. Even a correct implementation cannot turn an unverified input assumption into a biological fact.

What is reproducible, and what remains open

The completed local suite passed 281 tests, including actual GPU tests. Checks covered source parsing and the single exclusion, representation totals, split identity, held-out independence, decomposition agreement, rank-deficient projection, MDS self-projection, CPU/GPU objective agreement, model reload, and end-to-end fixture runs. All eight real-data bundles completed separately. Final audits checked unchanged source hashes, matching tumor manifests, full model widths, and the six shared sample preprocessing scopes. Warnings remained recorded; a passing suite was not treated as proof of data validity.

In the experiment project, preparation and fitting are separate commands. A fresh output path is required. Synthetic fixture mode checks the software and never counts as a real-data result: 

uv sync --locked
uv run python -m cancer_therapy prepare
uv run python -m cancer_therapy run M1 M2 M3 M4 M5 S0 S1 S2 --fixture --device cpu --output results/new-fixture
uv run python -m cancer_therapy run M1 M2 M3 M4 M5 S0 S1 S2 --device cuda --output results/new-full-data

The downloadable snapshot supports inspection of the reported aggregate results. It is not a distribution of the source matrices, trained weights, or the complete local artifact bundles. Those bundles also preserve fold summaries, PR and ROC curves, numerical histories, and identity-linked probabilities.

The next scientific step is to verify how the sample matrix was generated and what NA means. After that come checks for patient and cohort dependence, independent validation, and targeted tests of the competing explanations for S1 and S2. Changing those assumptions or tuning after seeing this final test would create a new experiment, not improve the evidence for this one.

The useful outcome is not just a table of eight scores. It is a workflow that makes prediction units, fit boundaries, device behavior, stopping conditions, and unsupported assumptions visible. A perfect test score is worth reporting. So is the reason not to trust it too far.
